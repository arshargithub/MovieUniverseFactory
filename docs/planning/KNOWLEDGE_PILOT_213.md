First read the named corpus and author expected task obligations separately from retrieval code. Freeze those fixtures before running selection. Reconcile every Markdown section of the bounded corpus to explicit record IDs or a explained disposition. This is agent-authored coverage, not independent human ground truth or full-history reconciliation. Keep a manual source audit and expose unknown task/entity/operation inputs rather than silently returning nothing.

Sequence: source review and frozen expectations → catalog/coverage → integrated packet and preflight → adversarial tests and fresh-process restart → real next-work planning packets and an application audit → closure report and production continuation. Track effort prospectively in KNOWLEDGE-213/pilot; initial context recovery precedes capture. Engineering tokens remain unknown. No arbitrary time cutoff; reassess if the pilot expands into a platform or fails its safety assumptions.

Reuse: retain stable record IDs and a rebuildable index, validate source changes before updating pins, and rerun coverage and affected task tests when records/relationships change. Never silently update a pin just to make a stale check pass. Conservative invalidation is acceptable for this first small corpus; fine-grained invalidation can follow measured need.

Completion floor: reproducible local build, explicit corpus coverage/gaps, measured finite retrieval tests, stale/authority/evidence failures that block the CLI gate, three real planning packets and application evidence for this pilot itself. No claims of automated visual judgment, universal recall, full production-runner enforcement or a newly qualified renderer.
