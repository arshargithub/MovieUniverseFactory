## Now versus later architecture

**Now:** portable records; stable universe/entity/asset/shot IDs; versioned canon and alternatives; approvals/decision history; provenance/licenses; logical artifact locations; budgeted immutable work packages; resumable job state; review feedback; narrowly reusable worker operations. Reuse current code and ledgers.

**Bridge:** Codex may supervise through those interfaces and read/write the same sources of truth. No accepted fact or essential production state should live solely in a Codex session. Transitional direct edits must be validated/imported with provenance rather than forming a hidden second database.

**Factory takeover:** a thin app and replaceable orchestrator use the same contracts. Test a new session/model, a source export/restore, a pinned production revision and safe job restart. A provider session ID is not project memory. “No loss” is an acceptance test and coverage requirement, not a guarantee inferred from copying files.

**Later unless required:** general arbitrary-rig support, sophisticated autonomous agents, remote collaboration, complex simulations, extra DCCs, automated publishing, recommendation analytics, and elaborate memory infrastructure. See [memory baseline](FACTORY_APP_AND_MEMORY_BASELINE.md); reconcile it with the original decision corpus before implementation freeze. Current official [Codex SDK documentation](https://learn.chatgpt.com/docs/codex-sdk) confirms programmatic integration is an option, not a requirement or a decision to make Codex the permanent runtime.
