# Conformance401 — executable scope, calibrated criteria and charged investment

Director401 approves closing400's audit findings inside397. This is an amendment
to that implementation, not new native allowance, model/spend authority, a new
workflow service or an artistic qualification. Original392–396 intent, serial330
planning,367/386micro-units and Director313AV remain in force.

## One scope decision and one eligible child

A public scope review's `decision` must equal its diagnostic `decision`. The next
plan must apply the exact reviewed diagnostic and first operation. No decision
can clear the reassessment requirement while another is executed.

For `split`, each child names `id`, `question`, `acceptance`, `depends_on`,
`proof_kind`, `criteria` and `operation_ids`. Children form an ordered DAG;
operation ownership is disjoint. The current plan contains exactly the current
child's operations and produces its proof kind. A dependent child consumes a
qualified canonical predecessor proof, not a narrative assertion of completion.

Input proofs name `id`, `kind`, `conditions`, `child`, an exact bound `artifact`
and `consumer_steps`. The conditions preserve the child, child-definition digest,
criterion-definition digest and reference-role/source digest. The controller
checks canonical proof validity, exact conditions and evidence bytes. The Bridge
checks that the consumer actually operates on the qualified native source.
Changing criteria/reference conditions requires a new qualified proof; relabeling
a transport output cannot establish target form. Bound source/engine changes still
require reviewed readmission; old production plans are not silently refreshed.

Native step subproofs are reviewed against actual returned artifacts and the
child's complete declared criterion set. The trusted parent derives child proof
conditions; the builder does not supply its own acceptance stamp. Director AV
cannot be self-passed. Artifact/condition checks cannot independently judge anatomy.

## Numerical criteria require actual calibration records

`calibration` and `negative_control` are path/SHA256 bindings to bounded JSON.
Each record has integer `schema:1`, `purpose` matching that field,
`conditions` exactly matching metric_key/comparator/threshold/coordinate_space/
profile/cells, and an explicit `applicability` statement.

Its `control` contains cell, a bound candidate (version/artifact bindings), and
a bound JSON measurement. Measurement candidate_digest/space/profile/cell match;
its finite scalar must pass the positive comparator and fail the negative one.
Missing, stale, incompatible or nondiscriminating evidence blocks admission and
review. A hash or comparator does not establish that the chosen metric is a valid
perceptual proxy or that its sensitivity is adequate: the agent must inspect and
justify those reference/control choices. Do not use synthetic test calibrations
as real horse/production calibration. Diagnostics can remain unqualified.

## Watch investment without inventing failed visual results

`feature_age` now counts charged reservations across the stable capability since
its latest retained meaningful proof, including pending attempts. Separate fields
report completed_result_age and unresolved cycle IDs. Pending is not visual FAIL;
old historical ages remain disclosed floors rather than a fabricated census.

The provisional10/20review/stop settings retain their source authority. The
capability shares an investment-review stamp across peers. Task-specific scope
remedies still bind that task's executable next operation. A renamed task cannot
reset investment or gain a new budget. Already reserved, fixed attempts can finish
work and review at the boundary; new attempts block. Retirement and all original/
ancestor/resource limits remain independently binding. No work is refunded.

Governance replay no longer aliases/mutates its input event objects. Pre401derived
review caches missing ordering recover from immutable full replay; corrupt caches
still block. Ledger events, native evidence and original task history are retained.

## Read-only scorecard and capture contract

Run `.venv/bin/python -m movie_factory.production_workflow scorecard --window 10`.
It returns canonical charged/completed/pending counts, historical task baselines,
allocation/weight configuration, conditional394scenario, rolling retained critical
feature gains/losses and qualified milestone-weight yield per charged cycle.
Changed/unconfigured weights give null production yield; R&D/discriminating failure
is not footage credit. Canonical proof retention is not a fresh media health scan.

The scorecard also joins existing operating-ledger observations. A meaningful
engineering/workflow plan–execute–review unit can emit `proxy_observed` with:
`name:plan_execute_review_cycle`, `count:1`, globally scoped `work_cycle_id`,
`lane:production|engineering|workflow_admin`, `cycle_status:reserved|completed|failed`,
`evidence_ref` and matching `evidence_binding`. Reserve at work start and close the
same ID; capture gaps stay explicit. Superseding corrections retain history;
conflicting or stale/unbound observations are reported, not quietly counted.
An already enrolled native cycle ID is not charged again as an admin cycle.
These observations describe work; they never grant native or resource authority.

Director-escape, handover and usable-output observations similarly use count1,
stable item_id and a bound source, with names `director_escape`,
`director_handover`, `usable_output`. They are explicit recorded observations,
not automatic semantic classification or artistic approval. Rates and cost per
usable output remain null without complete coverage/usage. A `measurement_coverage`
observation binds a bounded JSON record (`schema:1`, same purpose) with exact known
`cycle_ids` and `complete_fields` for director_escape/director_handover/usable_output.
Only observations attributed to those cycles enter its rates. Optional finite,
nonnegative provider_cost_usd/net_seconds support per-output metrics; net time
must explicitly exclude Director idle. Unknown resources stay null. An unknown
cycle, missing completeness, stale source or conflicting record rejects the
coverage claim. This is declared, auditable capture coverage, not an automatic
semantic-completeness guarantee. Operations, turns,
cycles, jobs, candidates and Director inputs remain distinct units.

Current globalC, whole-release weights and a future budget are not invented.
Original261/261and80/80remain exhausted; the inherited anatomy family remains
retired. A separately approved bounded package can allocate its own known scope
through the existing exact-approval APIs without pretending a whole-film forecast
exists. Source399horse and proposed8cycles remain unqualified/pending.

Software tests are necessary, not prospective evidence of fewer Director inputs
or studio-quality footage. That claim requires the next properly admitted unit
