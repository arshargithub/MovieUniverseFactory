The router-first workflow now has a real, locally exercised path from admitted
planning to numeric Blender authoring, saved derivative, fresh-process render
and output rejection. This qualifies the **supported main-chat workflow and

   admission. New operation types require reviewed handlers/tests, not code strings.

   and adjacent failures. A rejected prerequisite blocks successors. Direct

## Qualified operation envelope

`nihang_save` and `nihang_render` preserve selected native state and render a
bounded source-camera frame. `nihang_patch` accepts validated horse-rig quaternion
keys and bounded new mesh geometry with base-color/roughness values. All changes
are to disposable derivatives. Target names and exact recipes are frozen in the
plan; source masters are never overwritten. The actual test wrote an absolute
one-degree local head-control key and an off-camera triangle, not a one-degree
delta or a proposed improvement to the horse. Both persisted in a fresh process.

This is sufficient to start the next pose/representation proof through the
controlled path. It is not a claim that every future rig, garment, constraint,
simulation or animation operation is implemented. Adding a needed trusted
handler is routine in-scope engineering, with its own early control, not a reason
to bypass the workflow or ask the Director to choose an algorithm.
