# Sikh305 review failure: evidence and process assessment

Exchange306, 2026-10-18. **Production paused at the Director's request.**
This is an audit and proposed remediation, not construction, a new production
pass, or authorization to build a replacement orchestration app.

## Finding

The principal failure was applying and enforcing existing review obligations,
with inadequate perceptual evidence and overly schematic realization methods.
The relevant rules were present. Retrieval success did not produce application
success. More prose or a larger model context is not a sufficient remedy.

Withdraw305 as a satisfactory correction/handoff. Preserve its media, native,
technical receipts and explicit failed gates. The current principal proxy was
already an agreed limitation; it does not excuse supporting-action/terrain/FX
defects inside the agreed correction scope. No accepted Pashtun work is reopened.

## Why this reached the Director

1. **Wrong acceptance proxy.** Presence of phases, changed transforms, contact
   numbers, frame coverage and successful decoding substituted for the intended
   screen result. The reference was treated as an event list, not a performance
   standard. Geometry continuity substituted for environmental believability.
2. **Review missed interfaces and aftermath.** Dust was checked, but separate
   solid chips were not followed through settling and continued visibility.
   A road replacement retained differently shaded field-boundary geometry.
3. **Gate bypass.** `results/sikh305/delivery-13/production-gate.json` explicitly
   says `ready_for_review:false`. `scripts/sikh305_review.py` even asserts that
   false result while describing a development/perception-boundary handoff.
   This is not a silently passing software gate: it is a blocked gate whose
   outcome did not control delivery. A caveat does not supply Director consent
   to waive known in-scope failures.
4. **Scope and status were conflated.** Whole-production admission includes
   intentionally deferred principal work. The current supporting-scene work
   needs its own honest quality gate, inherited from the agreed scope—not a
   permanently red universal gate that becomes background noise. Narrowing a
   gate must never remove an in-scope defect after it fails.
5. **Missing perception was handled too late.**696 sequential thumbnails at
   220px width are not696 frames of real-time judgment. Playback/listening was
   explicitly NOT_RUN. That should have prompted an early capability plan,
   not a late general excuse to hand over. Several current failures are visible
   even in stills, so missing playback does not explain them away.

Existing authority already addresses these: exchanges161/168/249/264/282,
`CONTEXT_AND_DIRECTOR_REVIEW_CONTRACT.md`, `SHOT_BEAT_QUALITY_BRIEF.md`,
and decision0005. This audit therefore does **not** append another long rule
to AGENTS.md or claim that another retrieval test repairs artistic judgment.

## Recommended next package: enforce and calibrate the review workflow

**Proposed, not implemented by306.** Extend the existing local bridge with a
small control layer rather than replacing Codex or building the whole Factory.
The intended production benefit is fewer predictable failed reviews while
keeping the quality floor and Director's creative control intact.

1. **Compact authoritative task state.** One current intent/scope, protected
   versions, reference locations, live defects, evidence status and permitted
   next transition. Histories and full provenance remain on disk. Deduplicate
   always-loaded policies into a short contract/routing index only after a
   coverage check proves the binding rules were preserved. No blind deletion.
2. **Separate construction from assessment.** A review context receives actual
   candidate/reference evidence and the brief, not the builder's success story.
   It assesses the whole visible beat, then failure-seeking interfaces and
   aftermath. A separate context is not an independent expert guarantee or
   current authorization to dispatch other agents/providers.
3. **Reference-first evidence.** Predefine performance-critical relationships,
   visible landforms/material transitions and event lifecycle obligations.
   Use matched framing/scale plus time-labelled sequences at sufficient cadence;
   retain true durations and full recovery/aftermath. Resolve the temporal/audio
   review route before expensive finishing; do not mislabel snapshots as hearing
   or realtime perception. A video-capable review route, if proposed, needs its
   own proven capability, privacy, rights/cost and authority checks.
4. **Executable scoped handoff gate.** Separate file validity, scoped screen
   quality, full production admission and Director acceptance. An in-scope
   FAIL/NOT_RUN/stale item blocks the review-ready artifact transition. Diagnostic
   failure disclosure is allowed when requested or when a real method/authority
   decision is needed; it is not a completed-pass workaround. A local guard
   cannot prevent arbitrary chat text; claim enforcement only for paths actually
   wired through it. Do not weaken replay thresholds as part of this audit.
5. **Calibration before production.** Use305's four known failures as regression
   cases; accepted Pashtun as a scoped quality anchor, not a new Sikh animation
   oracle. Include an unprompted adjacent-defect search, a separate held-out
   negative/positive set and restart/compaction-resumption tests. Reject known
   failures for the right reason without indiscriminately rejecting everything.
   Do not call training on these cases independent generalization evidence.
6. **Measure behavior, not paperwork.** Track known-failure false acceptance,
   false rejection, scoped gate bypasses, stale-pass carryover, escaped defects,
   unnecessary Director reviews and context recovery cost. Measure prompt/input
   tokens where telemetry supplies them, not byte-based guesses. Report sample
   counts and limits; no promised improvement percentage.

Deliverable: a compact current-state/review packet, tested handoff transition,
calibration results and an honest remaining perception-capability decision if
needed. Excluded: production changes, new rendered sequence, new model/service
adoption, paid calls, broad knowledge migration, cloud work or full custom app.
Exit: failures cannot reach review-ready through the supported delivery path;
fresh-context recovery preserves scope/defects; finite calibration detects the
known failures; missing temporal/audio evidence has an explicit viable route or
blocker. Then resume the existing correction scope with representative proofs
before another complete finishing render. Director-facing production handoff
remains the integrated sequence, not another incremental horse improvement.
