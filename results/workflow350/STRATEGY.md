# Retrospective integration strategy

Implement349 within the existing event controller, not a second runner. A pure
event projection detects repeated outcomes and maintains orthogonal obligations;
SQLite append-only events persist it. Existing correction counters and stage
transitions remain authoritative. All new production tasks enter the policy;
legacy tasks require explicit reviewed migration, never automatic repinning.

Hook final reviews, challenge results, native-step reviews and worker terminal
outcomes. Guard builder dispatch, native capability/job acquisition and delivery,
including replayed receipts. Recovery and replanning may collect evidence/change
methods but cannot erase obligations. Share persistent requirement identities and
proof validity; do not claim file hashes establish semantic equivalence.

Earliest integrated proof: synthetic production final rejection triggers a scoped
hold after recurrence, restart retains it, a response can admit a diagnostic test
without closing the finding, and an exhausted task stays exhausted. Then add
native failure/review hooks with mocked workers, regression tests and frozen
historical cases. Preserve a false-review semantic negative control.

No Blender, provider, external API, install or upload. No live qualification calls.
One process for tests unless the existing suite tests concurrency. Tests and
inspection use project Python. Do not migrate live52/12 state. Exit requires
tested admission paths, a documented API/migration plan, historical countercases,
and explicit distinction between software enforcement and production quality.
