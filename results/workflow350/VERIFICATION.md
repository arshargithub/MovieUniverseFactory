# Retrospective workflow verification

The local retrospective policy is implemented and passes **452 focused offline
tests** across15 test modules, plus **seven frozen historical classifications**.
The [software knowledge gate](knowledge-gate.json) passes. This closes350's

## What the tests establish

- Repeated failed requirements trigger warning at two distinct attempts and an
  obligation at three. Multiple views/callbacks of one attempt do not count as
  separate variants. Explicit falsifiers/regressions trigger immediately.
- Final reviews, planning challenges, native-step review and pre-candidate worker
  failures feed the same append-only event policy. A simulated transaction failure
  rolls back the native review rather than storing it without the finding.
- Obligations survive restart, replanning and authorized allowance extensions.
  A manual exhaustion path found during review is now covered centrally.
- Responses require separate challenged admission for the current plan. Effective
  closure requires new matching evidence; worker success, a negative-control PASS
  or a stale response does not qualify. Failed/inconclusive tests reopen review.
- New findings invalidate stale native capabilities and delivery receipts.
  Evidence, proof versions and test plans are checked again at use.
- Existing proof manifests preserve conditions. Changed rig/use requires targeted
  revalidation; registered dependents block on relevant regression while unrelated
  tasks continue. Removing a dependency or changing requirements cannot erase
  the prior obligations.
- Legacy migration is explicit, preserves limits and opens evidence reconciliation.
  Lightweight task routing remains lightweight. Oversized retrospective packets
  block instead of silently truncating active requirements.

The test suite includes existing workflow, native bridge/recovery, staged runner,
resource routing, knowledge, context and review-control regressions. Worker calls
are mocked; no Blender process or provider is used.

## Implementation review and remaining boundaries

were inspected, alongside controller submission, recovery, allowance extension,
heavy-job lease and delivery. Direct legacy scripts and arbitrary shell commands
are not covered by OS enforcement; router-first instructions prohibit bypass.

working agent performs reasoning and submits the source-bound response/challenge.

classify semantic method similarity or merge aliases. Such changes need explicit
reconciliation. Active findings route immediately through controller packets;
curated global-knowledge promotion remains a separate source-reviewed step.
