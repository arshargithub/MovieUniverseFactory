# Planning substage implementation and qualification

## Critique before construction

1. Decomposition can become a paperwork pipeline. Each artifact must change the
   next stage's constraints; the controller must reject dropped obligations,
   unsupported sources and skipped stages. Named lenses are not application.
2. Summaries can launder authority or omit the Director's actual intent. Every
   stage retains original direction and reference-role contracts, source IDs,
   status and scope. Hypotheses cannot silently become approved preferences.
3. Retrieval is incomplete. Require a source/relationship reconciliation and
   explicit gaps beside the fresh pilot packet. Missing catalog entries are not
   evidence of irrelevance. Do not rebuild a universal graph for this pass.
4. A rigid waterfall can entrench an unsuitable method. Challenge must return a
   specific failure to grounding, derivation or strategy. Failed output may expose
   planning omissions too. Reuse only unaffected upstream artifacts; invalidate
   downstream evidence. Corrections share one persisted package allowance.
5. Self-review can repeat the author's conviction. Separate the challenge's
   dispatch/input from strategy authorship, omit self-admission prose, retain
   original sources and require observations/counterexamples. Fresh context is
   not independent expertise or a proven perceptual judge.
6. Prior321 had many correct requirements already. The method must explain why
   it should work, its evidence status, alternatives and earliest representative
   falsification. No amount of plan validation substitutes for actual pose/frame
   evidence and Director-owned full-speed/audio review.
7. Extra stages increase calls/context and create new failure surfaces. Use
   bounded stage packets, serial execution, durable events, idempotence and
   existing call/resource leases. Lightweight workflows bypass production
   planning explicitly; no agent per lens. Never manufacture savings percentages.
8. Early proof must precede expensive commitment. Strategy requires an ordered
   dependency graph and a first representative proof. This pass can enforce the
   planning contract, not a Blender authoring bridge that does not yet exist.

## Implementation scope and proof

Extend the existing controller with four planning substages, not another harness.
Grounding binds seven context domains and the fresh learning packet; derivation
maps context/learning obligations and per-beat lenses to requirements; strategy
binds methods, interfaces, ordered proof and protected authority; challenge admits,
routes targeted repair or records a material Director decision. Every substage
uses the current input digest and a new ticket. Source/engine changes fail closed.

Use existing planner/reviewer model roles (challenge is reviewer); no live model
selection or call. Mock serial integration must exercise all six stages through
output review, restart/recovery, stage skipping, source drift, obligation loss,
repair routing, decision boundaries and conserved call/correction limits. Keep a
well-formed wrong-method negative control to expose semantic limitations.

Adapt four330 regression cases from328 retrospectively, preserving knowledge of
later feedback. Freeze a prospective Nihang planning package separately without
claiming production execution or quality. No accepted media copied or modified.
Exit: regression evidence, honest capability boundaries, source-aware continuation
instructions and one next production-facing proof. Local code/design commits
separate. Checkpoint330 remote range requires scope/secret review; no broad push
or backup claim without it.
